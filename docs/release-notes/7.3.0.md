# 7.3.0

User-visible behavior changes. `CHANGELOG.md` carries the full merged pull request and issue list.

## OpenTelemetry semantic-convention conformance

Span names, span kinds and attribute names change to follow the RabbitMQ semantic convention (#1980):

- **`messaging.rabbitmq.delivery_tag` is renamed to `messaging.rabbitmq.message.delivery_tag`, with no transition period.** The old name is gone in 7.3.0. It carried the value correctly, so any dashboard, alert or saved query keyed on it returns **no results** after upgrading, silently, rather than erroring. Search your observability configuration for the old name before you upgrade. A dual-emit period was considered and rejected: it would trade one silent break now for the same break in 8.0.0, plus a duplicate tag on every fetch and delivery span until then.
- Messaging span names and span kinds change. Span names now include the exchange; `messaging.destination.name` is composed rather than the bare exchange; `BasicGet` spans are `Client` rather than `Consumer`; and an empty `BasicGet` reports `fetch` with `messaging.rabbitmq.message.received` set to `false`. Set `UseRoutingKeyAsOperationName` to `false` for bare operation names.
- **`messaging.message.body.size` and `messaging.message.envelope.size` are no longer emitted by default.** Both are Opt-In in the convention, which asks instrumentation to populate them only when configured to. Set `IncludeMessageSizes` on `RabbitMQTracingOptions`, or per connection on `ConnectionTracingOptions`, to get them back.
- `messaging.destination.name`, `messaging.operation.name` and `messaging.operation.type` are now supplied at span creation, so samplers can key on them, and they survive on spans sampled as `PropagationData`. `network.transport` is newly emitted.
- Three attributes this client emits are its own rather than the convention's: `messaging.rabbitmq.message.received`, `messaging.rabbitmq.connection.is_reconnection` and `messaging.rabbitmq.connection.automatic_recovery`. The registry defines only `messaging.rabbitmq.destination.routing_key` and `messaging.rabbitmq.message.delivery_tag` under that prefix. Treat the other three as this client's, not as specified telemetry: they may be renamed or withdrawn.
- Every `messaging.*` attribute in the convention is Development rather than Stable, so these names may move again.

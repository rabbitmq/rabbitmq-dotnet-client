# 7.3.1

User-visible behavior changes. `CHANGELOG.md` carries the full merged pull request and issue list.

## Tracing

- The consumer dispatch loops start with no current activity, so consumer callbacks no longer see the span that was current when the channel was created, and a delivery span without an upstream parent, because `UsePublisherAsParent` is off or the message carries no trace context, is a root span. It used to become a child of that span, and after automatic recovery of the long-finished `connection attempt` span (#2154).
- `messaging.message.body.size` and `messaging.message.envelope.size` on one publish span follow the same `IncludeMessageSizes` decision (#2154).
- A trace context extracted from a message is marked remote, so a `ParentBased` sampler decides on the publisher's sampling flag (#2154).
- A propagator that throws while extracting a context no longer drops the delivery: the exception is logged to the `rabbitmq-client` EventSource and the message is traced without its upstream context (#2154).
- With the default process-wide extractor, `DistributedContextPropagator.Current` is called for every delivery, including messages without trace headers, so `OpenTelemetryPropagator` resets `Baggage.Current` for each delivery instead of letting one message's baggage reach the next. A propagator set there must accept a `null` carrier, as one set on `ConnectionTracingOptions` already must (#2154).
